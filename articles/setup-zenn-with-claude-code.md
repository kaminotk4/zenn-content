## 構築のゴール

今回のゴールはシンプルに3つだ。

1. Zennで記事を書いて公開できる状態にする
2. GitHubリポジトリと連携して、ローカルから記事を管理する
3. 環境構築そのものをClaude Codeに任せる

「3を任せる」が今回のキモだ。環境構築は「調べながら手を動かす」作業が多く、時間を溶かしやすい。ここをAIに任せることで、週5時間の制約を守れるかを試したかった。

---

## 前提環境

- OS：Windows
- Node.js：インストール済み
- GitHubアカウント：**個人用を新規作成**

GitHubアカウントについては後述するが、副業は本業と環境を分けることを強く推奨する。今回はそのために個人用アカウントを新たに作った。

---

## やったこと（時系列で）

### 1. 個人用GitHubアカウントを作成

仕事で使っているGitHubアカウントとは別に、副業専用のアカウントを作った。

なぜ分けるのかは後で詳しく書くが、「分けておいてよかった」と後から思うことになる。

### 2. Zennアカウントを作成

Zennのトップページからアカウント登録。Googleアカウントでログインできるので、こちらは迷うことなく完了した。

### 3. GitHubリポジトリを作成（zenn-content）

個人用GitHubアカウントで `zenn-content` という名前のリポジトリを作成した。公開設定はPublicでも問題ない（Zenn CLIの仕様上、記事ファイルは公開される前提になっている）。

### 4. ZennとGitHubリポジトリを連携

Zennのダッシュボードから「GitHubとの連携」を設定し、作成したリポジトリを指定した。これでリポジトリにpushすれば自動的にZennへ反映される仕組みができた。

### 5. Claude Codeをインストール

```
npm install -g @anthropic-ai/claude-code
```

これだけだ。ただしここで最初のつまづきがあった（次のセクションで詳しく書く）。

### 6. 作業ディレクトリを作ってClaude Codeを起動

```
mkdir zenn-work
cd zenn-work
claude
```

### 7. Claude Codeに指示を出すだけで環境が整った

Claude Codeに伝えたのはこれだけだ。

> 「GitHubのリポジトリをクローンして、Zenn CLIの初期設定をしてください。リポジトリのURLは〇〇です」

あとはClaude Codeが勝手に動いた。`git clone`、`npm install`、`npx zenn init`、ディレクトリ構造の確認……一連の作業を自分で分解して実行してくれた。私がやったのは指示を出したことと、途中でいくつかの確認に答えたことだけだ。

## つまづいた点（ここが一番の価値）

環境構築はスムーズには進まなかった。3つのつまづきがあった。

### つまづき①：PowerShellの実行ポリシーエラー

`npm install -g @anthropic-ai/claude-code` を実行しようとしたら、PowerShellがスクリプトの実行を拒否した。

```
このシステムではスクリプトの実行が無効になっているため、ファイル〇〇を読み込めません。
```

Windowsのデフォルトではスクリプト実行が制限されている。PowerShellを管理者として起動し、以下のコマンドで解決した。

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Claude Codeがエラーの原因と解決策を即座に提示してくれたので、「何が起きているか」を理解した上で対処できた。

### つまづき②：Claude CodeにはPro/Maxプランが必要

Claude Codeは無料プランでは使えない。AnthropicのPro（月20ドル）またはMaxプランが必要だ。

私はもともとClaude Proを契約していたのでここはクリアできたが、「とりあえず試してみよう」と思って無料プランのまま試した場合、ここで止まる。

副業でClaude Codeを活用したい方は、まずプランの確認を。

### つまづき③：git pushで認証エラー（最大の罠）

これが今回最も時間を食いそうだった問題だ。

個人用GitHubアカウントで作ったリポジトリに `git push` しようとしたところ、認証エラーが出て弾かれた。

原因はWindowsの**資格情報マネージャー**にあった。

仕事でGitHubを使っているPCには、仕事用GitHubアカウントの認証情報がWindowsの資格情報マネージャーにキャッシュされていた。`git push` しようとすると、個人用アカウントではなく、仕事用アカウントの古い認証情報が使われてしまい、認証に失敗していた。

Claude Codeが原因を特定してくれた。

> 「Windowsの資格情報マネージャーに以前のGitHub認証情報が残っています。コントロールパネルから `git:https://github.com` の認証情報を削除して、個人用アカウントで認証し直してください」

手順通りに対処したところ、pushが通った。

一人でやっていたら「なぜかpushできない」「認証設定を何度見直してもわからない」という状態で時間を溶かしていたと思う。

## Claude Codeに任せてみた所感

環境構築を通じて感じたことをまとめる。

**「こうしたい」を伝えれば手順を分解して実行してくれる**

仕様や目的を伝えれば、必要な手順を自分で考えて実行する。「次は何のコマンドを打てばいいか」を調べる時間がほぼ消えた。

**エラーが出ても自分で原因を切り分けて直す**

今回の認証エラーのように、エラーメッセージから原因を特定して解決策を提示してくれる。自分でスタックオーバーフローを調べ回る必要がない。

**環境構築のような調べ物が多い作業こそ、AIに任せる価値が大きい**

初めての技術スタックは「何を調べればいいかわからない」という状態になりがちだ。Claude Codeはその「最初の地図」を提供してくれる。

**人間がやることは「方針の判断」と「アカウントの使い分けの確認」だった**

本業と副業のアカウントを分けるかどうか、どのリポジトリを使うか、どの設定を適用するか──こういった判断は人間がやるべきことだ。逆に言えば、それ以外はかなりの部分をClaude Codeに任せられた。

## まとめ

ゼロから記事公開できる環境まで、つまづきながらも数時間で到達できた。

特に**認証まわりは一人だと時間を溶かしがちな部分**だ。「GitHubにpushできない」「なぜか権限エラーになる」というトラブルは、Windowsの資格情報マネージャーという見えにくい場所が原因になることがある。AIが原因を切り分けて対処してくれるのは、実際に体験してみると相当助かる。

また、**副業は本業とアカウント・環境を分けることを強く推奨する**。今回の認証トラブルはまさにアカウントが混在していたことが原因だった。副業を始めるなら、最初から専用アカウントを作っておいた方がいい。
