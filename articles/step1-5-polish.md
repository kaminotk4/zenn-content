## はじめに

前回の記事では、生年月日から太陽・月・金星の3天体を計算して星座を表示する「自分占い（無料）」の実装が完了しました。計算精度も確認済み、動作も問題なし。

でもそこで一度立ち止まりました。

**「動いてはいる。でも、これを他人に見せられるか？」**

答えはノーでした。

動くものと使えるものは別物です。STEP1.5は、その間にある「磨き込み」の工程。完璧主義を抑えて「60点で出す」を意識しつつ、最低限の品質を担保するための作業をまとめます。

## レビューをしてみた

まず自分でアプリを触り、妻にも使ってもらいました。開発者の目では見えていなかった問題が、すぐに出てきました。

### 自分のレビュー

率直に言うと、デザインが「いかにも占いアプリ」でした。

- ダークパープルのグラデーション背景
- 丸みのある半透明カード（glassmorphism）
- 紫のアクセントカラー

それ自体は悪くないのですが、2025年の今見ると「どこかで見たことある感じ」がする。差別化にならない。

文章も短くて浅いと感じました。星座ごとに1〜2行の説明文が書いてあるのですが、読んでも「で、私はどうすればいいの？」という感じが残る。情報として正しいけど、寄り添いがない。

### 妻のレビュー

妻は普段から占いを楽しんでいるので、ユーザー視点のフィードバックをもらえました。

「もっと読みたくなる文章にしてほしい」

具体的に聞いたら、こういうことでした。

> 「自分の良いところだけ書いてあっても信憑性がない。弱点も書いてあって、でもそこから立ち直れる感じがあると、ぐっと来る」

さらに「こういう流れが好き」と提案してくれたのが、3部構成でした。

1. **良い性質**（強み・才能）
2. **気をつけるべき点**（裏返しの弱点）
3. **だからこそ、こんな過ごし方をしてね**（具体的な行動アドバイス）

これはいいと思いました。単なる性格説明ではなく、読んだ後に「次どうするか」がわかる。

## 文章を直した

妻の提案をもとに、全12星座×3天体（太陽・月・金星）の解説文を書き直しました。

**変更前：** 性格や傾向を説明するだけの1〜2文
**変更後：** ①良い性質→②気をつける点→③行動アドバイスの3部構成、各フィールド150〜200文字

書き直す中で、バグも一つ発見しました。

結果画面の「恋愛傾向まとめ」セクションに、**太陽星座の `love` フィールドの文章が表示されていた**のです。金星星座が表示されるべき場所に、太陽の文章が入っていました。

これは実装時に `positions.find(p => p.planet === 'venus')` ではなく `sunPos.sign` を参照していたことが原因。地味ですが、占いアプリとして致命的なミスです。

修正した上で、さらに一歩進めました。「恋愛傾向まとめ」は、金星星座の説明をそのまま流用するのではなく、**太陽・月・金星の3天体を統合した独自の文章**を生成するようにしました。

```typescript
export function getCombinedLoveSummary(
  sunSign: ZodiacSign,
  moonSign: ZodiacSign,
  venusSign: ZodiacSign
): string {
  const sun = ZODIAC_DESCRIPTIONS[sunSign];
  const moon = ZODIAC_DESCRIPTIONS[moonSign];
  const venus = ZODIAC_DESCRIPTIONS[venusSign];
  return `${sun.nameJa}として生まれたあなたの恋愛は、${LOVE_SUN_TRAIT[sunSign]}という姿勢が根底にあります。${moon.nameJa}の月が示す${LOVE_MOON_TRAIT[moonSign]}内面は、大切な人への接し方に温かみと深みを与えています。そして${venus.nameJa}の金星が輝かせる${LOVE_VENUS_TRAIT[venusSign]}愛情スタイルが、あなたをかけがえない存在にしてくれます。`;
}
```

星座名を自然に文中に織り込みながら、3天体の意味を一文で統合できました。

### 解説文をさらに拡充した

妻から「もっと文章を長くしてほしい」というフィードバックをもらい、全12星座×3天体の解説文を150〜200文字から250〜300文字にさらに拡充した。

また「恋愛傾向まとめ」は、太陽・月・金星のエレメントの組み合わせ（火×水、風×地など）によって文章の切り口が変わるよう改善した。テンプレートに星座名を当てはめるだけでなく、組み合わせごとに異なる語りかけ調の文章が生成される。

## デザインを刷新した

文章が整ったので、次はデザインです。

Claude Codeに `frontend-design` スキルを使ってデザイン方針を提案させました。提示されたコンセプトは **"Warm Celestial Editorial"**。

### コンセプト

**占い＝冷たい紫**という先入観を壊す、温かみのある高級天文エディトリアル。

| 要素 | 変更前 | 変更後 |
|------|--------|--------|
| 背景 | 冷たいネイビー `#0d0d2b` | 深い暖色チャコール `#100e0a` |
| アクセント | 紫 `#a78bfa` | シャンパンゴールド `#c9a86c` |
| 見出しフォント | ヒラギノ系ゴシック | Cormorant Garamond（細くて優雅なセリフ体）|
| 本文フォント | 同上 | Noto Serif JP（明朝体）|
| カード | glassmorphism（blur＋半透明） | 1pxゴールドボーダー＋薄いウォームオーバーレイ |

### ポイント

- **ゴールドアクセント：** ラグジュアリーアプリの定番。紫から変えるだけで一気に品が出る
- **明朝体：** 日本語の縦の流れに合った書体で、サンセリフとは違う落ち着きが出る
- **星座シンボルを背景装飾に：** 各カードの背景に大きく薄く星座記号を配置（CSS `content: var(--sign-symbol)`）
- **角丸なし：** `border-radius: 0` の直線的なボーダーで、エディトリアル感を演出

## まとめ

STEP1.5を通じて実感したことが3つあります。

### 「動くもの」と「使えるもの」は別物

機能が動くことと、人に使ってもらえることは全然違います。動くものを作るのは技術の話で、使えるものにするのはデザインと言葉の話。エンジニアは前者が得意で後者を後回しにしがちですが、ユーザーが触るのは後者です。

### レビューは身近な人が一番早くて正確

UIを外部ツールで評価する方法もありますが、信頼できる人に実際に触ってもらうのが圧倒的に速いです。妻のフィードバックは5分で出てきて、的確で、かつ「こうしてほしい」という方向まで含んでいました。
